## What's supported

### Supported actions

This connector supports:

- [Read Actions](/read-actions), including full historic backfill and incremental read for all supported objects.
- [Write Actions](/write-actions), including Delete.
- [Proxy Actions](/proxy-actions), using the base URL `https://my.jumpapp.com/enterprise/graphql`.

### Supported objects

The Jump connector supports the following objects:

<Note>
**Writes are limited by Jump's API:**

- **Contacts only:** `contacts` is the only object that can be created, updated, and deleted. See Jump's [mutations reference](https://my.jumpapp.com/enterprise/documentation/reference?tab=mutations).
- **Writable fields:** contact writes accept `firstName`, `lastName`, and `email` only. Any other field is rejected. Reads return `name` instead of `firstName` and `lastName`, and `name` cannot be written.
- **Create:** `firstName`, `lastName`, and `email` are all required. If a contact with the same email already exists, Jump returns the existing contact instead of creating a new one.
- **User ID:** contacts are created, updated, and deleted on behalf of the Jump user whose User ID the customer enters when installing the integration. Reads are not limited to that user.
</Note>

**Contact updates and incremental read:** Jump does not change a contact's `updatedAt` when the contact is updated through the API, so contacts updated through Write Actions are not included in later incremental reads.

## Before you get started

To use the Jump connector, you'll need an API key from your Jump account. Jump lists API access under its Enterprise plan; see [Jump's pricing](https://jump.ai/pricing). Here's how to get the API key:

1. Sign in to the [Jump homepage](https://my.jumpapp.com) as an account owner (only account owners can create API keys).
2. In the lower-right corner of the homepage, click **Profile & settings**.
3. Click **Account settings**.
4. Navigate to **API**.
5. Click **Create API Key**.
6. Enter a name and select scopes.
7. Save the key, then copy the generated key.

![Jump API Key](/images/provider-guides/jump.gif)

API keys are scoped to your Jump account and provide access to all data within it.

For more details, see the [Jump Authentication documentation](https://my.jumpapp.com/enterprise/documentation/authentication).

When installing the integration, the customer also enters a **User ID**. This is the `id` (for example, `usr_...`) of the Jump user on whose behalf contacts are created, updated, and deleted. You can find it with the [`users` query](https://my.jumpapp.com/enterprise/documentation/reference?tab=queries#query-users) in the Jump API.

## Using the connector

This connector uses **API Key authentication**, so you do not need to configure a Provider App before getting started. (Provider Apps are only required for providers using the **OAuth2 Authorization Code grant type**.)

To integrate with Jump:

- Create a manifest file like the [example above](#example-integration).
- Deploy it using the [amp CLI](/cli/overview).
- If you are using Read Actions, create a [destination](/destinations).
- Embed the [InstallIntegration](/embeddable-ui-components#install-integration) UI component, which will prompt the customer for their API key and User ID.
- Start using the connector!
  - If your integration has [Read Actions](/read-actions), you'll start getting webhook messages.
  - If your integration has [Write Actions](/write-actions), you can start making API calls to our Write API. To delete contacts, first [enable deletion](/write-actions#enabling-deletion-for-an-object) for the `contacts` object in the installation.
  - If your integration has [Proxy Actions](/proxy-actions), you can start making Proxy API calls.
