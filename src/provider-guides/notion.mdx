## What's supported

### Supported actions

This connector supports:

- [Read Actions](/read-actions), including historic backfill for supported objects. Incremental reads apply to `file_uploads` only (filtered by last edited time). Each scheduled read for `users` returns the current workspace user list.
- [Write Actions](/write-actions) (create only for `file_uploads`).
- [Proxy Actions](/proxy-actions), using the base URL `https://api.notion.com`.
- Subscribe and Delete actions are not currently supported.

### Notes and limitations

- **Workspace access:** During installation, the end user chooses which Notion pages and databases the integration can access. Many Notion API calls only work for content that was shared with the integration. See [Notion’s authorization guide](https://developers.notion.com/docs/authorization).
- **Read coverage:** Ampersand Read currently syncs **users** and **file uploads**—the workspace lists that Notion exposes without a parent page or database id. **Pages, databases, blocks, and comments** are not available through Read Actions in this connector. Notion often requires a specific parent or Search to list those resources, which does not provide a dependable incremental sync for scheduled reads.
- **Users (`read`):** Notion’s user list does not support time-based filtering. Each scheduled read returns the workspace user list for the connection.
- **File uploads (`read`):** Reads can be narrowed with `since` and `until` using each upload’s last edited time.
- **File uploads (`write`):** Create only. Updating or deleting uploads through this connector is not supported.
- **Proxy:** You can call other [Notion API endpoints](https://developers.notion.com/reference/intro) through Proxy Actions when your integration has the right capabilities and page access. Always send a current `Notion-Version` header on requests, as described in Notion’s documentation.

## Before you get started

To connect Notion with Ampersand, you need a [Notion workspace](https://www.notion.so) and an **OAuth public integration** in the [Notion Developer portal](https://www.notion.so/profile/integrations).

From that integration you will need:

- **OAuth client ID** (integration ID)
- **OAuth client secret** (integration secret)

You will use these credentials when you connect the integration in Ampersand. Your customers complete Notion’s OAuth flow when they install your app and select which pages to share.

For background, see [Notion’s OAuth authorization documentation](https://developers.notion.com/docs/authorization).

### Create a Notion OAuth integration

1. Sign in and open the [Notion Developer portal](https://www.notion.so/profile/integrations).
2. Click **New integration** (or create a **Public** integration, depending on how your portal is labeled).
3. Enter a name and select the workspace that will own the integration.
4. Under **OAuth domain & URIs** (or **Redirect URIs**), add the Ampersand redirect URI:

   `https://api.withampersand.com/callbacks/v1/oauth`

5. Save the integration.
6. Open the integration **Configuration** (or **Secrets**) tab and copy the **OAuth client ID** and **OAuth client secret**. Store them securely; you will enter them in Ampersand.

During customer installation, Notion prompts the user to **Allow access** and to **Select pages** for the integration. Only content the user shares is available to the API for that connection.

## Add your Notion integration to Ampersand

1. Log in to your [Ampersand Console](https://console.withampersand.com).

2. Select the project where you want to create a Notion integration.

   ![Ampersand project selection](/images/provider-guides/dd47b7a-Ampersand.png)

3. Select **Provider apps**.

4. Select _Notion_ from the **Provider** list.

5. Enter the **OAuth client ID** in the **Client ID** field and the **OAuth client secret** in the **Client Secret** field.

6. Click **Save changes**.

## Using the connector

To start integrating with Notion:

- Create a manifest file like the [example](https://github.com/amp-labs/samples/blob/main/notion/amp.yaml).
- Deploy it using the [amp CLI](/cli/overview).
- If you are using Read Actions, create a [destination](/destinations).
- Embed the [InstallIntegration](/embeddable-ui-components#install-integration) UI component. The UI guides your customer through Notion OAuth and page selection.
- Start using the connector:
  - With [Read Actions](/read-actions), synced records are delivered to your destination on the schedule you define.
  - With [Write Actions](/write-actions), use the Write API to create **file uploads** (see [Notion’s create file upload reference](https://developers.notion.com/reference/create-a-file)).
  - With [Proxy Actions](/proxy-actions), call the Notion API at `https://api.notion.com` using the customer’s OAuth token.
