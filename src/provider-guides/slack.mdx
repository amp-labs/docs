## What's supported

### Supported actions

The Slack integration is available through two connectors:

- **Bot connector** — provider name: `slack`. This connector uses Slack bot token scopes.
- **User connector** — provider name: `slackUserScope`. This connector uses Slack user token scopes.

Both connectors support:
- [Read Actions](/read-actions), including full historic backfill and incremental read.
- [Write Actions](/write-actions).
- [Subscribe Actions](/subscribe-actions).
- [Proxy Actions](/proxy-actions), using the base URL `https://slack.com/api`.

Both connectors use the same Slack app, OAuth configuration, client ID, client secret, and Ampersand redirect URI.
The difference between them is the Slack token type and the scopes configured for that token.

Choose the connector whose supported objects and operations match your use case.
The required Slack scopes depend on the connector and the Slack API methods used.

### Supported objects

The following matrix shows object and operation support for each Slack connector:
- **✅** — supported.
- **🚫** — the connector supports the object, but not that operation. Write may mean both or one of create/update.
- **empty** — the object is not available through that connector.

Write indicates support for one or both of the following operations: create and update.
Object access also depends on the Slack scopes granted to the installed app and, where applicable, the authorizing user's Slack permissions.

export function renderCellValue(value) {
  if (typeof value === "boolean") {
    return value ? <Check/> : <Cross/>;
  }

  if (typeof value === "string" && value.startsWith("<")) {
    return <span dangerouslySetInnerHTML={{__html: value}}/>;
  }

  return value;
}

<Note>
  To receive messages, thread replies, edits and deletions, subscribe to the `messages` object.
  `conversations` covers channel lifecycle events such as creation, rename and archive, not what is
  said inside them, so subscribing to it alone will not deliver a single message.

  `messages` is subscribe-only: Slack has no endpoint that reads a single message, so the record is
  delivered in the event payload instead. See [Subscribing to message
  events](#subscribing-to-message-events) for how to configure it and what the webhook contains.
</Note>

### Choose a connector

Use the **Bot connector** (`slack`) when your integration needs to operate with Slack bot token scopes.
This is the typical choice for integrations that act as an installed Slack app or bot.

Use the **User connector** (`slackUserScope`) when your integration needs to use Slack user token scopes
and perform actions on behalf of the authorizing Slack user.

### Subscribing to message events

Slack delivers every message as an event of type [`message`](https://docs.slack.dev/reference/events/message), distinguished by a [subtype](https://docs.slack.dev/reference/events/message#subtypes).
Ampersand maps them onto a single object, `messages`:

| Slack event                          | Subscribe event type |
|--------------------------------------|----------------------|
| `message`, `thread_broadcast`        | `create`             |
| `message_changed`                    | `update`             |
| `message_deleted`                    | `delete`             |

A thread reply is a plain `message` event carrying a `thread_ts`.
Slack does not populate a `message_replied` subtype, so watch for `thread_ts` to identify replies.

#### The record arrives in the webhook

`messages` behaves differently from every other subscribe object.
Slack has no endpoint that fetches a single message by id, so Ampersand cannot look the record up after the event arrives.
Instead, the full message is delivered from the event payload itself.

Two consequences follow:

- Do not add `messages` to your read objects. It is not a readable Slack object, and a manifest that reads it will fail to deploy to your customers.
- `fields` and `mappedFields` are empty, because there is no read action to inherit them from. Read the message out of `raw` instead.

#### Watch all fields on updates

Slack does not say which parts of a message changed when it sends `message_changed`.
Set `watchFieldsAuto: all` on the update event, or edits will not be delivered:

```yaml
subscribe:
  objects:
    - objectName: messages
      destination: messageWebhook
      inheritFieldsAndMapping: true
      createEvent:
        enabled: always
      updateEvent:
        enabled: always
        watchFieldsAuto: all
      deleteEvent:
        enabled: always
```

`inheritFieldsAndMapping` is required whenever create, update or delete events are set.
For `messages` it resolves to an empty field selection, which is expected.

#### Scopes and event subscriptions

Which event subscription you need depends on the conversation type you want messages from.
Each one requires the matching history scope, added under **Event Subscriptions** and **OAuth & Permissions** in your Slack app:

| Conversation type     | Event subscription | Scope required     |
|-----------------------|--------------------|--------------------|
| Public channels       | `message.channels` | `channels:history` |
| Private channels      | `message.groups`   | `groups:history`   |
| Direct messages       | `message.im`       | `im:history`       |
| Group direct messages | `message.mpim`     | `mpim:history`     |

Add these as **Bot Token Scopes** for the Bot connector (`slack`), or as **User Token Scopes** for the User connector (`slackUserScope`).
Subscribe only to the conversation types you need, since each one adds volume.

You do not subscribe to subtypes.
Edits, deletions and thread replies all arrive through the subscriptions above, and Ampersand derives the event type from the payload:

| Subscribe event type | Slack payload                                         |
|----------------------|-------------------------------------------------------|
| `create`             | a `message` with no subtype, or subtype `thread_broadcast` |
| `update`             | subtype `message_changed`                             |
| `delete`             | subtype `message_deleted`                             |

So subscribing to `message.channels` alone gives you creates, updates and deletes for public channels.

#### Set up a message subscription

<Steps>
  <Step title="Configure your Slack app">
    Add the event subscriptions and scopes for the conversation types you want, using the table above.
    Invite the bot to the channels you want messages from, since scopes alone do not deliver events for channels it has not joined.
  </Step>

  <Step title="Add the subscribe object to your manifest">
    Use the `messages` block shown above.
    Do not add `messages` to your read objects.
  </Step>

  <Step title="Deploy the manifest">
    Deploy with the [amp CLI](/cli/overview).
    Create the [destination](/destinations) your subscribe object names, if it does not exist yet.
  </Step>

  <Step title="Have your customer install the integration">
    Embed the [InstallIntegration](/embeddable-ui-components#install-integration) component.
    Your customer authorizes Slack and the installation is created.
  </Step>

  <Step title="Add `messages` to the installation">
    The install component cannot add `messages` on its own, because Slack publishes no field metadata for it.
    Until it can, add the object to the installation with [Update an installation](/reference/installation/update-an-installation):

    ```bash
    curl -X PATCH \
      -H "X-Api-Key: $AMPERSAND_API_KEY" \
      -H "Content-Type: application/json" \
      "https://api.withampersand.com/v1/projects/$PROJECT_ID/integrations/$INTEGRATION_ID/installations/$INSTALLATION_ID" \
      -d '{
      "updateMask": ["config.content.read.objects.messages"],
      "installation": {
        "config": {
          "content": {
            "read": {
              "objects": {
                "messages": {
                  "disabled": false,
                  "objectName": "messages",
                  "destination": "messageWebhook",
                  "selectedFieldMappings": {},
                  "selectedFields": {
                    "ts": true,
                    "text": true,
                    "user": true,
                    "channel": true,
                    "type": true,
                    "thread_ts": true,
                    "event_ts": true
                  }
                }
              }
            }
          }
        }
      }
    }'
    ```

    Three details matter:

    - The update mask must name the object, as `config.content.read.objects.messages`. A bare `config` is rejected.
    - Because the mask names one object, the patch merges. Read objects already in the config are left alone.
    - `destination` is required here and must match a destination in your project. Your manifest has no `messages` read object for it to inherit one from.

    Repeat this if the installation is later updated through the install component, which rebuilds the config and drops the object.
  </Step>

  <Step title="Post a message and check your destination">
    Send a message in a channel the bot has joined.
    A create event should arrive at your destination with the message in `raw`.
  </Step>
</Steps>

#### Other Slack limits

A bot only receives events for channels it has been invited to, so adding the scopes is not enough on its own.
With the User connector, the authorizing user receives events for the conversations they are a member of.

Slack caps event delivery at 30,000 events per workspace per hour and expects your endpoint to acknowledge within three seconds.

## Before you get started

To connect Slack with Ampersand, you will need [a Slack Developer Account](https://api.slack.com/developer-program/join).

Once your account is created, you'll need to create an app in Slack, configure the Ampersand redirect URI within the app, and obtain the following credentials from your app:

- Client ID
- Client Secret
- **Bot scopes** and/or **User scopes**

You will then use these credentials to connect your application to Ampersand.

### Create a Slack Account

Here's how you can sign up for a Slack account:

- Go to the [Slack Sign Up page](https://api.slack.com/developer-program/join).
- Sign up using your preferred method and verify your email.

### Creating a Slack App

Follow the steps below to create a Slack app and add the Ampersand redirect URL.

1. Log in to your [Slack Developer](https://slack.com/signin) account.

2. Click **Your Apps**.

3. Click the **Create New App** button.

4. In the **Create a Slack App** pop-up window, enter the **App Name** and select the **Development Slack Workspace** where you want to develop your app. Click **Create App**.

5. In the left-hand sidebar, navigate to **OAuth & Permissions**.

6. In the **Redirect URLs** section, click **Add a Redirect URL** and enter the Ampersand redirect URL: `https://api.withampersand.com/callbacks/v1/oauth`. 

7. Click **Add** and then **Save URLs**.

8. In the **Scopes** section, add the necessary **Bot Token Scopes**/**User Token Scopes** for your app by clicking on **Add an OAuth Scope** and selecting the required scopes.

   ![Slack App Creation](/images/provider-guides/23f128f-slack1.gif)

   You will find the **Client ID** and **Client Secret** in the **Basic Information** section. Note these credentials, as you will need them to connect your app to Ampersand.

## Add Your Slack App Info to Ampersand

1. Log in to your [Ampersand Dashboard](https://dashboard.withampersand.com).

2. Select the project where you want to create a Slack integration.

   ![Ampersand Project Selection](/images/provider-guides/31a6a12-Ampersand.png)

3. Select **Provider Apps**.

4. Select **Slack Bot Scope** or **Slack User Scope** from the **Provider** list.

5. Enter the previously obtained **Client ID** in the **Client ID** field and the **Client Secret** in the **Client Secret** field.

6. Enter the **bot scopes** or **user scopes** set for your application in _Slack_.

   ![Ampersand Integration](/images/provider-guides/88f33d5-slack2.gif)

7. Click **Save Changes**.

## Using the connector

To start integrating with Slack:
- Create a manifest file like the [example above](https://github.com/amp-labs/samples/blob/main/slack/amp.yaml).
- Deploy it using the [amp CLI](/cli/overview).
- If you are using [Read Actions](/read-actions), create a [destination](/destinations).
- Embed the [InstallIntegration](/embeddable-ui-components#install-integration) UI component. The UI component will prompt the customer for their Slack authorization.
- Start using the connector.
   - If your integration has [Read Actions](/read-actions), you'll start getting webhook messages.
   - If your integration has [Write Actions](/write-actions), you can start making API calls to our Write API.
   - If your integration has [Proxy Actions](/proxy-actions), you can start making Proxy API calls.
