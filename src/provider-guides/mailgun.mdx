## What's supported

### Supported actions

This connector supports:

- [Read Actions](/read-actions), including full historic backfill. Please note that incremental read is supported only for `account/templates`, `accounts/subaccounts`, `analytics/logs`, `analytics/tags`, `bounces`, `complaints`, `domains`, `domains/credentials`, `dynamic_pools/history`, `forwards`, `keys`, `lists`, `routes`, `templates`, `thresholds/alerts/send`, `thresholds/hits`, `thresholds/limits`, `unsubscribes`, `webhooks` and `whitelists` currently. For all other objects, a full read of the Mailgun instance will be done per scheduled read.
- [Write Actions](/write-actions).
- [Proxy Actions](/proxy-actions), using the base URL `https://api.mailgun.net`.

\* For these objects, incremental read picks up newly created records only. Mailgun has no last-updated timestamp for them, so changes to existing records are not picked up.

\*\* Limited to the log retention of the customer's Mailgun plan. A full historic backfill returns the last day of logs.

<Note>
**Writes are limited by Mailgun's API:**

- **Create-only:** `messages`, `bounces`, `complaints`, `unsubscribes`, and `whitelists` cannot be updated.
- **No delete:** `messages` and `lists/members` cannot be deleted.
- **`lists/members`:** include a `list_address` field naming the parent mailing list.
</Note>

### Example integration

To define an integration for Mailgun, create a manifest file that looks like this:

```YAML
# amp.yaml
specVersion: 1.0.0
integrations:
  - name: mailgunIntegration
    displayName: My Mailgun Integration
    provider: mailgun
    read:
      objects:
        - objectName: bounces
          destination: myWebhook
        - objectName: lists
          destination: myWebhook
    write:
      objects:
        - objectName: lists
        - objectName: messages
    proxy:
      enabled: true
```

## Before you get started

To connect Mailgun with Ampersand, you will need a [Mailgun account](https://signup.mailgun.com/new/signup).

### Creating an API key for Mailgun

1. Log in to the [Mailgun dashboard](https://app.mailgun.com).
2. Go to **Account Settings** > **API keys** and click **Create key**. If your plan supports key roles, choose **Admin** or **Developer** so the key can read and write.
3. Copy the key. Mailgun shows it only once.

![Mailgun API Key](/images/provider-guides/mailgun.gif)

Use an account API key. Domain sending keys can only send messages.

When installing the integration, the customer also provides:
- **Domain name:** the Mailgun sending domain, as listed under **Send** > **Domains** in the Mailgun dashboard (for example, `mg.example.com`). It is used by domain-scoped objects such as `bounces`, `messages`, and `templates`.
- **Region:** `us` (default) or `eu`, matching the region the domain was created in. Proxy Actions always use the US base URL.

## Using the connector

This connector uses Basic Auth, which means that you do not need to set up a Provider App before getting started. (Provider apps are only required for providers that use OAuth2 Authorization Code grant type.)

To start integrating with Mailgun:
- Create a manifest file like the [example above](#example-integration).
- Deploy it using the [amp CLI](/cli/overview).
- If you are using Read Actions, create a [destination](/destinations).
- Embed the [InstallIntegration](/embeddable-ui-components#install-integration) UI component. The UI component will prompt the customer for their username and password, Mailgun domain name, and region.
- Start using the connector!
   - If your integration has [Read Actions](/read-actions), you'll start getting webhook messages.
   - If your integration has [Write Actions](/write-actions), you can start making API calls to our Write API.
   - If your integration has [Proxy Actions](/proxy-actions), you can start making Proxy API calls.

## Credential format for Mailgun

Mailgun uses HTTP Basic Authentication with a non-standard credential format. The fields in the installation UI do not correspond to a Mailgun login. Instead:
- **Username**: Always `api`.
- **Password**: The Mailgun API key.

For more detail, see [Mailgun's authentication documentation](https://documentation.mailgun.com/docs/mailgun/api-reference/authentication/). The UI components will display this link, so that your users can successfully provide their credentials.
