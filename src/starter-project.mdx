The [starter project](https://github.com/amp-labs/starter-project) is a small, working application you can clone and run. Use it when you would rather see a live integration first and read the details afterwards.

It contains two things:

<CardGroup cols={2}>
  <Card title="A React app" icon="react" href="https://github.com/amp-labs/starter-project/blob/main/src/App.tsx">
    A minimal React and Vite app that embeds the `InstallIntegration` component, so you can watch a customer connect their account.
  </Card>
  <Card title="Three integrations" icon="file-code" href="https://github.com/amp-labs/starter-project/tree/main/integrations">
    Pick between HubSpot, Salesforce, and GitHub, or add your own.
  </Card>
</CardGroup>

## Before you start

Setting up the accounts and credentials takes longer than running the app itself. Budget around twenty minutes for these steps the first time. You'll also need Git and Node.js 18 or later.

<Steps>
  <Step title="Create an Ampersand project">
    Sign up for a [free Ampersand account](https://dashboard.withampersand.com/sign-up) and follow the prompts to create a project.
  </Step>
  <Step title="Create an API key">
    In the dashboard, open [API keys](https://dashboard.withampersand.com/projects/_/api-keys) and create one. Since the key is used by the React app, choose **UI Library** when asked where you will use it. You will paste it into the app later.

    <Accordion title="Which key type should I use, and is it safe in the browser?">
      Choose **UI Library**. These keys can only call the endpoints the UI components need, like creating installations. They can't make write or proxy calls, so they're fine for trying things out in a frontend. For production, switch to [JWT authentication](/embeddable-ui-components#jwt-authentication), which is more secure. Keep server keys, which can call every endpoint, on your backend.
    </Accordion>
  </Step>
  <Step title="Create a destination named `defaultWebhook`">
    In [Destinations](https://dashboard.withampersand.com/projects/_/destinations), create a webhook destination called `defaultWebhook`. If you do not have an endpoint to point it at, [play.svix.com](https://play.svix.com) gives you a disposable one that shows incoming payloads in the browser, which is ideal for a first run.
  </Step>
  <Step title="Set up the provider">
    You can start with any of the three included integrations. Each provider guide walks you through creating an account and an app:

    - **HubSpot** reads and writes contacts and companies, and subscribes to contact changes. Follow the [HubSpot provider guide](/provider-guides/hubspot).
    - **Salesforce** reads and writes accounts and contacts. Follow the [Salesforce provider guide](/provider-guides/salesforce).
    - **GitHub** reads and writes gists. Follow the [GitHub provider guide](/provider-guides/github).

    You can also use other integrations from our [samples repo](https://github.com/amp-labs/samples), or browse [our provider guides](/provider-guides/overview) for all supported integrations. Learn more in [Make it yours](#make-it-yours).
  </Step>
  <Step title="Install the CLI">
    Install the [Ampersand CLI](/cli/overview) and run `amp login` to authenticate.
  </Step>
</Steps>

## Run it

<Steps>
  <Step title="Clone and install">
    ```bash
    git clone https://github.com/amp-labs/starter-project.git
    cd starter-project
    npm install
    ```
  </Step>
  <Step title="Deploy an integration">
    Pick the one you set up:

    <Tabs>
      <Tab title="HubSpot">
        ```bash
        amp deploy integrations/hubspot -p <your-project-name>
        ```
        Integration name: `hubspotCRM`
      </Tab>
      <Tab title="Salesforce">
        ```bash
        amp deploy integrations/salesforce -p <your-project-name>
        ```
        Integration name: `readAndWriteSalesforce`
      </Tab>
      <Tab title="GitHub">
        ```bash
        amp deploy integrations/github -p <your-project-name>
        ```
        Integration name: `githubIntegration`
      </Tab>
    </Tabs>

    This creates a [revision](/concepts#revision) of the integration from its `amp.yaml`. Nothing syncs yet, because no customer has installed it.
  </Step>
  <Step title="Point the app at your project">
    In `src/App.tsx`, replace `MY-PROJECT-NAME` and `MY-API-KEY` with your project name and API key, and set `integration` to the name from the step above.
  </Step>
  <Step title="Start the app">
    ```bash
    npm run dev
    ```
    Open `http://localhost:5173` and connect an account. You'll see a four-step setup: **Connect**, **Select objects**, **Configure**, and **Review**. These screens show Salesforce:

    <img src="/images/quickstart-wizard-connect.png" alt="Step 1 of the setup, Connect: the customer enters their Salesforce workspace and clicks Next. The steps Select Objects, Configure, and Review are shown at the top." style={{ maxWidth: "460px", width: "100%" }} />

    In **Configure**, the customer maps your fields to theirs. `Country` here comes from a `mapToName` in your `amp.yaml`.

    <img src="/images/quickstart-wizard-configure.png" alt="Step 3 of the setup, Configure: for the Account object, the customer opens a dropdown of their Salesforce fields to choose which one maps to Country." style={{ maxWidth: "460px", width: "100%" }} />

    <Accordion title="I connected an account, but nothing is happening. What's wrong?">
      Check that you deployed the integration before connecting, and that the `integration` name in `App.tsx` matches your `amp.yaml`. Without a deployed integration, connecting creates a connection but not an installation.
    </Accordion>
  </Step>
  <Step title="Check that it worked">
    The starter integrations read existing records first, so results start arriving at your `defaultWebhook` destination soon after setup. After that, new and updated records keep arriving. If you used [play.svix.com](https://play.svix.com), they show up on that page. To see every read, write, and proxy call and whether it succeeded, go to **Integrations** in the dashboard, open your integration, and select the installation.

    <Accordion title="What does a message look like?">
      Here's a shortened example:

      ```json
      {
        "action": "read",
        "provider": "salesforce",
        "objectName": "Contact",
        "groupRef": "xyz-company",
        "readType": "scheduled",
        "result": [
          {
            "fields": { "id": "001Dp00000P8QurIAF", "firstname": "Sally", "lastname": "Jones" },
            "mappedFields": { "pronoun": "she" }
          }
        ]
      }
      ```

      `fields` holds the fields you asked for, and `mappedFields` holds the ones each customer mapped. See [webhook messages](/destinations/webhooks#read-action-webhooks) for every field.
    </Accordion>

    That's it: you have a working integration.
  </Step>
</Steps>

## What the code does

The whole integration surface is one component. `AmpersandProvider` holds your project credentials, and `InstallIntegration` renders the connect and configure flow your customers see:

```tsx src/App.tsx
<AmpersandProvider options={options}>
  <InstallIntegration
    integration={integration}
    consumerName="demo-user-name"
    consumerRef="demo-user-id"
    groupName="demo-company-name"
    groupRef="demo-company-id"
    // @ts-expect-error -- opt into wizard variant
    variant="wizard"
  />
</AmpersandProvider>
```

`consumerRef` and `groupRef` identify which of your customers is installing; in your app, they come from your user and account records. `variant="wizard"` turns on the step-by-step setup, which is in [beta](/embeddable-ui-components#wizard-mode-beta). See [Prebuilt UI components](/embeddable-ui-components) for every prop.

## Make it yours

<Steps>
  <Step title="Swap the integration">
    Add a folder under `integrations/` with your own `amp.yaml`, or one from the [samples repository](https://github.com/amp-labs/samples), and deploy it the same way. Then set `integration` in `App.tsx` to its `name`, and make sure its `destination` exists in the dashboard. See the [manifest reference](/manifest-reference) for every field.
  </Step>
  <Step title="Redeploy after changes">
    Run `amp deploy` again whenever you edit your `amp.yaml`. You only need one `amp.yaml` for all your customers, and it can hold multiple integrations.
  </Step>
  <Step title="Get ready for production">
    Switch from an API key to [JWT authentication](/embeddable-ui-components#jwt-authentication), and use a separate Ampersand project for production, with its own provider apps. See [Dev and prod environments](/dev-and-prod-environments).
  </Step>
</Steps>
