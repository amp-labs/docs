---
title: "Search actions"
---

**Use a search action to look up specific records in your customer's SaaS on demand**, like finding a contact by email. You specify filter criteria, and the matching records come back right away in the API response.

<Note>
The Search API returns only a single page of provider results and is intended for narrow, targeted queries.
</Note>

## Enabling search for an object

Search does not require a separate action type in the manifest. Instead, it uses the `read` action. An object is searchable when it's defined under `read` in your `amp.yaml` **and** it's in the installation's config without `disabled: true`.

Like every read object, it needs a `destination`.

There are two ways to make sure an object is searchable:

### Option 1: Set `enabled: "always"` in the manifest

Set `enabled: "always"` on an object to enable it for every installation, so it's always searchable.

```YAML YAML
specVersion: 1.0.0
integrations:
  - name: readSalesforce
    provider: salesforce
    read:
      objects:
        - objectName: contact
          destination: contactWebhook
          enabled: "always"
```

See [Always-enabled objects](/read-actions#always-enabled-objects) for how this affects new and existing installations.

### Option 2: Include the object in the installation config

Without `enabled: "always"`, the object is searchable for an installation only if it's in that installation's config: the customer selected it during setup, or you added it through the API. If it's missing, search returns `Config not found for object`.

```YAML YAML
specVersion: 1.0.0
integrations:
  - name: readSalesforce
    provider: salesforce
    read:
      objects:
        - objectName: contact
          destination: contactWebhook
```

With this manifest, search works for installations whose config includes `contact`. Setting `disabled: true` on the object also stops search:

```json
// This would disable search for the contact object — avoid this if you want search to work
{
  "read": {
    "objects": {
      "contact": {
        "disabled": true
      }
    }
  }
}
```

## Execute a search

You can call the [search API](/reference/search/search-records) to search for records in a customer's SaaS instance. The results are returned synchronously in the API response.

Filters use the `eq` (equals) operator, which is currently the only one supported. Field mappings defined in `amp.yaml` and mappings selected by users during installation time will be respected and applied. See [Object and Field Mapping](/object-and-field-mapping) for more information.

Request example

```bash
curl --location 'https://search.withampersand.com/v1/projects/04bbc51e-7b5e-43c4-a453-e6d77ee55cb2/integrations/9a22a71b-d90b-4118-84c6-558771f3f6db?groupRef=searchTest-group-ref' \
  --header 'x-amp-request-type: search' \
  --header 'Content-Type: application/json' \
  --header 'x-api-key: <YOUR_API_KEY>' \
  --data '{
    "objectName": "account",
    "fieldFilters": [
      {
        "fieldName": "phoneNumber", // this is mapped field name selected by users during installation or in `amp.yaml`
        "operator": "eq",
        "value": "1234567890"
      },
      {
        "fieldName": "fax", // unmapped field name matching provider's field name.
        "operator": "eq",
        "value": "9876543210"
      }
    ]
  }'
```

Response example
```json
{
    "results": [
        {
            "fields": {
                "id": "00000000000001",
                "name": "test account"
            },
            "id": "00000000000001",
            "mappedFields": { // mapped fields are returned in separate field in the result object.
                "phoneNumber": "1234567890"  
            },
            "raw": {
                "Id": "00000000000001",
                "Name": "test account",
                "Phone": "1234567890",
                "attributes": {
                    "type": "Account",
                    "url": "/services/data/v60.0/sobjects/Account/00000000000001"
                }
            }
        }
    ]
}
```

### Search with a raw filter

Instead of `fieldFilters`, you can search with a [raw filter](/read-actions#filter-with-a-raw-filter) in the provider's own query syntax. A search applies a raw filter exactly as a read action does, so it's a quick way to check a filter before adding it to an installation.

```bash
curl --location 'https://search.withampersand.com/v1/projects/04bbc51e-7b5e-43c4-a453-e6d77ee55cb2/integrations/9a22a71b-d90b-4118-84c6-558771f3f6db?groupRef=searchTest-group-ref' \
  --header 'x-amp-request-type: search' \
  --header 'Content-Type: application/json' \
  --header 'x-api-key: <YOUR_API_KEY>' \
  --data '{
    "objectName": "account",
    "rawFilter": {
      "type": "soql",
      "filter": "AnnualRevenue > 1000000 OR NumberOfEmployees > 500"
    }
  }'
```

- A request needs exactly one of `fieldFilters` or `rawFilter`.
- Field names in a raw filter are the provider's own. Field mappings are not applied to them.
- Raw filters are currently only supported for **Salesforce** (CRM Module). See [Salesforce raw filters](/provider-guides/salesforce#raw-filters-soql).
